## 一、本轮改动（老板三次打回：「这里还是没有改变！我要的就是整个软件随着主题而改变」）

0.6.5 走 nativeTheme 只联动了菜单条的**明暗一轴**，且老板实机仍判「没变」。
本轮治本 = **Windows 撤掉原生菜单栏，改由 renderer 自绘菜单带（MenuBarBand）**：
「文件/编辑/视图/帮助」四组入口吃全套 `--sc-color-*` token，
**明暗 × 配色派系 × 质感**三轴全部随主题实时变。

| 落点 | 文件 |
| :-- | :-- |
| 自绘菜单带组件（动作单源=menu.click/role 回 main） | `renderer/src/menu/MenuBarBand.tsx`（新） |
| 菜单带样式（全 token，pixel-borders 扫描面内） | `renderer/src/menu/MenuBarBand.css`（新） |
| main：Win 下 `setApplicationMenu(null)` + `menu:click`/`menu:role` 两通道 | `src/main/index.ts` |
| 动作表/role 表下沉 shared（preload 可见） | `src/shared/ipc.ts` |
| preload 桥 `menu.click/role` | `src/preload/index.ts` |
| 挂载：app-frame 纵骨架（菜单带 + 主体 flex 列） | `renderer/src/App.tsx` / `App.css` |
| linear 灰面 / glass 半透纳入菜单带 | `packages/ui/src/looks.css` |
| 布局 token `--sc-layout-menu-band: 30px` | `packages/ui/src/tokens.css` |
| Win 侧热键补偿（Ctrl+N / Ctrl+± / Ctrl+0） | `renderer/src/App.tsx` |

macOS 保留原生菜单（OS 惯例，其 accelerator 照常注册，不双触发）。

## 三、已知坑（写入 pitfalls）

1. 开合 click 必须 `stopPropagation`：ui `Menu` 的文档级「点空白关闭」监听会把
   刚打开的下拉同帧关掉——jsdom 复现不了，真机才现。
2. Chromium 计算色新形态 `color(srgb r g b / a)`：探针 `rgbOf` 必须两形态都认。
3. vitest 默认环境 node，jsdom 用例文件头必须 `// @vitest-environment jsdom`。

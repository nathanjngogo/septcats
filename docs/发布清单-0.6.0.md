3. `bash apps/desktop/scripts/publish.sh`，环境变量 **`SEPTCATS_FEED_KEY` 传私钥文件路径**（`apps/desktop/tmp/feed-keys/septcats-feed.key`，不是内容——0.5.0 踩过）；链内顺序=归一化 latest.yml（空格→点）→ sign → verify。
4. 拉取核对一律 `gh release download`（curl 直连 GitHub 本机慢/截断——0.5.0 实测）；整包全量 sha512 用 `curl -sL -C - --retry 8 --retry-all-errors` 断点续传补流（慢链截断不重拉整包）。
5. 线上硬核对四件：feed `verify` 过 + yml `version: 0.6.0` + `.sig` 在场 + yml sha512 = 本地实算 = 线上实拉（三方全等，字节数精确）。
6. `gh release edit v0.6.0 --notes-file …`（双语）+ `gh release view latest` 与 API `releases/latest` 双证 Latest、draft=false、assets 四件套齐。
7. 本地 `git tag v0.6.0` 打在发布源 commit（与 GitHub tag 双落）；0.5.0 用户自动更新走验签 feed——**同号不得重发**（字节变即升号）。

## 风险登记

- feed latest=0.5.0 → 0.6.0：无 schema 迁移（导出/GC 均只读或纯 DELETE 墓碑路径，op-log v3 零新增类型）；老版本打开新数据不受影响（未写入新格式）。
- 便携包导入=「换库」操作，**唯一有破坏性窗口的功能**：三段式+失败回滚+备份在场才允许落库是硬闸；发布说明必须写明「导入会替换当前库，先自动备份可撤销」。
- T81 GC 默认关（dry-run 起步），发布不带行为突变。

## 1. 问题与目标

现状：用户反复创建结构相同的页面（例如「会议纪要」= 标题 + 参会人 + 议题 + 结论；「周报」= 三个数据库视图），每次都从空白页手工搭结构，成本高且容易漏项。

目标：**把「一个已搭好的页/库」变成可复用的起点**。成功判据（一句话）：新建页时能从模板一键得到结构完整的页，且不引入任何外部依赖（纯本地）。

## 2. 三个方案（推荐 A）

### 方案 A · 页面模板（推荐，≈3–4 人日）

- **另存为模板**：页面右键/更多菜单 → 「另存为模板」（模板含：块树内容、标题、图标、页面属性开关）。
- **从模板新建**：侧栏「新建页面」旁的下拉 / 命令面板（Ctrl+K）输入「从模板新建」→ 选模板 → 生成新页（新页是**独立副本**，与模板后续改动解耦）。
- **模板库管理**：设置或侧栏一个「模板」分组，可重命名/删除/预览；模板存数据根 `templates/`，随同步文件夹一起走（跨设备一致）。
- **不做**：模板市场、分享/导入、模板变量。

### 方案 B · A + 数据库模板（≈6–8 人日）

在 A 之上，允许**数据库（表格/看板/日历视图 + 属性 schema + 视图配置）**另存为模板，新建库时可选。
代价：需序列化 dbview schema 与视图配置、处理版本迁移；风险集中在「schema 演化后老模板反序列化」。

### 方案 C · B + 模板占位符语言（不建议二期做）

模板正文支持 `{{date}}`/`{{title}}`/`{{weekday}}` 等占位符，创建时替换。
代价：引入一门小语言（解析、转义、错误提示、文档），用户预期会被拉高（「为什么没有 `{{if}}`」）。**建议留到三期或社区呼声足够时再评估。**

## 3. 若选 A：关键设计点（已替你先想过的坑）

| 点 | 决定 | 理由 |
|---|---|---|
| 副本语义 | 复制，不引用 | 模板改动不应回改历史页；实现也简单（块树深拷贝 + 新 id） |
| 模板自身是不是一个页面？ | **不是**，存独立 `templates/` 目录 | 避免模板页混进 pages 树/搜索/最近，污染用户空间 |
| 与同步的关系 | 模板是数据根下的普通文件 → 随 sync 走 | 跨设备一致，无需新协议 |
| 搜索是否索引模板 | **否** | 模板不是用户内容；避免检索污染（也让 FTS 无需改动） |
| 空模板/超大模板 | 限制：模板块数上限（如 500 块）+ 体积上限，超限时报可读错 | 防止误把 10 万块大页存成模板拖慢新建 |

## 4. 验收方式（若选 A）

**层测**：模板序列化/反序列化 roundtrip；另存为模板不改原页；从模板新建 → 新页 id 全不同、结构一致；删除模板不影响已创建页。
**真机 CDP**：搭一个 3 级结构页 → 另存为模板 → 重启 → 从模板新建 → 结构完整 → 原页与模板互不影响 → 双主题目检。
**红线**：模板不进搜索索引、不进「最近」，不新增网络调用。

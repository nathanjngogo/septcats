## 1. 核心决策点：附件走哪条数据面（要老板拍板）

### 方案 A（推荐）：附件独立进 `files/` 目录，段只带引用
同步目录布局（§6.3 原样兑现）：
```
syncDir/
  segments/…        # 现状不动（账本真相层保持纯 op，小、快、可加密）
  snapshots/…       # 现状不动
  files/<hash><ext> # 新增：内容寻址附件原样落盘（与本地 attachments/ 同命名）
```
- 上行：本地新附件/新引用 → 后台队列把 `attachments/<name>` 原子拷入 `files/<name>`
  （临时文件+rename，照 T80-04 不留半成品纪律）。
- 下行：merger 应用块后发现 `attachment://<hash>` 本地缺失 → 从远端 `files/<hash>*`
  拉取（扩展名变体用 findHashFile 同口径匹配）→ **sha256 复验**（不符=隔离告警，
  学 quarantine）→ 原子落 `attachments/`。缺附件期间 UI 已是占位态（现有协议 miss 行为），不新增回归。
- 引用集=本地 attachments 对账（复用 T83-02 六路引用枚举！同一套判定代码第二次吃到）。

**为什么推荐 A**：
1. 内容寻址天然去重/幂等/无冲突（同 hash=同内容，两台机同时传同一文件互不踩）；
2. 102MB 视频塞不进 256KB 事件段——B 方案必须分段封装+重组，复杂度爆炸；
3. 账本保持纯 op（D2 决策不动），段尺寸/watermark/快照逻辑零改动；
4. 附件失败只影响显示（占位），**不损数据真相**——故障半径小一级；
5. 网盘客户端搬运整文件比搬运「不断追加的大段」稳定（S3 网盘副本去重口径直接复用）。

### 方案 B（否决留档）：附件字节 base64 附在 op payload
段会膨胀（×4/3）、256KB 上限撞穿、账本被二进制污染、重放变慢、删除语义难做。列出仅为完整性。

## 2. 护栏清单（Q6 契约逐条对应）

| 计划要求 | 落法 |
|---|---|
| 流式分块读写 | 拷贝/拉取用 stream pipe（64KB chunk），禁整文件 readFileSync（大附件 OOM） |
| 磁盘余量预检 | 传输前 `checkDiskSpace`（目标盘剩余 > 文件大小×1.2 才动手），不足→队列挂起+状态告警 |
| 后台队列+失败退避 | 复用 runtime 退避模式（指数 backoff，上限 5min）；单文件失败不阻断队列 |
| 并发 ≤3 | 队列 worker 数钉 3 |
| 进度可视 | SyncStatusSnapshot 扩 `attachments:{pending,active,failedBytes}`；面板/托盘行消费（见 T84-01） |
| 可暂停/取消 | setEnabled(false) / 显式暂停钮 = 停队列（在途文件回滚删除临时件，不留半截） |

## 3. 与既有机制的关系
- **加密（M8.7）**：段 DEK 开启时对 `files/` 内容同样加密（信封同套；附件流式分块 AES-256-GCM，块头带 IV/序号）。加密关闭=明文。**注意**：网盘上加密附件仍不可读（设计如此，U6）。
- **快照/retention（M8.4）**：`files/` 的 GC 独立做——引用集来自段重放+本地账本（复用 T83-02 planAssetGc 的 conservative 口径 + 30 天保护期），所有设备 watermark 越过才可删（§M8.4 原则）。一期可先只做「只增不删」（网盘空间换简单），删除列入后续。
- **便携包（T80-01/02）**：files/ 布局与便携包 `files/` 清单同构，导出/导入链复用，不加第三套格式。
- **同步开关**：附件队列挂在 syncEnabled 总开关内，默认关（隐私红线不动）。

## 4. 验收题库（DoD 草案）
1. 双 runtime（junction 共享目录，M8b 先例）：A 提交带图页 → B 追平且**图片字节逐字可见**；
2. 100MB 大附件传输中 UI 输入延迟不红（主进程 CPU<20%，§M8.9 同款测法）；
3. 拔电注入：半截 `files/` 临时件 → 重启自愈（复验 hash 不过→隔离重传）；
4. 网盘双写同 hash → 幂等（sha 相同=成功，非错误）；
5. 加密开启：A 明文/B 拉到密文可解；密钥不一致红条同段口径；
6. 暂停/恢复/setEnabled(false)：队列即停，无半截残留；
7. 磁盘预检注入满盘 → 挂起告警不崩。

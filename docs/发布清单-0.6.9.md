## 一、本轮改什么（老板圈图 image_83fc8f.png：「这上面为什么没有跟着主题走？」）

逐像素解剖老板裁的 1189×66 顶带：`y2–31` = **OS 原生标题栏**（#F2F2F2 死灰白，
paper 派系暖白根本没进去）、`y32–60` = 0.6.6 自绘菜单带、`y62+` = 主区（暖褐已透）。
根因 = OS 原生标题栏由 Windows DWM 绘制，Electron 只能告诉它「明/暗」两档
（nativeTheme.themeSource）——**配色派系与质感两轴 OS 不理会**。CSS 禁区，此前无解。

**治本（T89-01）**：
| 层 | 改动 |
| :-- | :-- |
| main 建窗 | Win 下 `titleBarStyle:'hidden' + titleBarOverlay`（**hidden 必须配 overlay 才生效**——0.6.6 只试 hidden 是 no-op 的根因）；撤原生标题文字区，OS 在右上画真·窗口按钮（悬停红 X/键盘可达保留，原生边框/贴边吸附/圆角不动） |
| renderer | 新组件 `TitleBarBand`（🐈 品牌 + 名 + 拖拽区 + 138px overlay 预留区），整带只吃 `var(--sc-*)` token；双击最大化=OS 对 HTCAPTION 原生行为零 JS；macOS 不挂（惯例） |
| 配色→OS 桥 | 新通道 `theme:chrome`：MutationObserver 盯 documentElement 的 data-theme/data-palette/data-look（三轴唯一真相挂点）→ 实测 `--sc-color-canvas`/`--sc-color-ink` → 推 main `setTitleBarOverlay` + 预绘底色；`resolveChromeOverlay` 纯函数收窄非法色（fail-safe 回落明暗态 token） |
| looks.css | linear 灰面 / glass 半透面纳入 `.titleb_band`（与菜单带同 chrome 面） |

新通道：`window:getState` + `window:state`（maximized 初值/广播，探针断言面）。

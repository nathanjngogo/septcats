## 一、T89-01（image_83fc8f.png 逐像素解剖）

老板裁的 1189×66 顶带：`y2–31` = **OS 原生标题栏**（#F2F2F2 死灰白，paper 派系暖白根本没进去）、`y32–60` = 0.6.6 自绘菜单带、`y62+` = 主区（暖褐已透）。根因 = OS 原生标题栏由 Windows DWM 绘制，Electron 只能告诉它「明/暗」两档（nativeTheme.themeSource）——**配色派系与质感两轴 OS 不理会**。CSS 禁区，此前无解。

| 层 | 改动 |
| :-- | :-- |
| main 建窗 | Win 下 `titleBarStyle:'hidden' + titleBarOverlay`（**hidden 必须配 overlay 才生效**——0.6.6 只试 hidden 是 no-op 的根因）；撤原生标题文字区，OS 在右上画真·窗口按钮（悬停红 X/键盘可达保留，原生边框/贴边吸附/圆角不动） |
| renderer | 新组件 `TitleBarBand`（🐈 品牌 + 名 + 拖拽区 + 138px overlay 预留区），整带只吃 `var(--sc-*)` token；双击最大化=OS 对 HTCAPTION 原生行为零 JS；macOS 不挂（惯例） |
| 配色→OS 桥 | 通道 `theme:chrome`：MutationObserver 盯 documentElement 的 data-theme/data-palette/data-look（三轴唯一真相挂点）→ 实测 `--sc-color-canvas`/`--sc-color-ink` → 推 main `setTitleBarOverlay` + 预绘底色；`resolveChromeOverlay` 纯函数收窄非法色（fail-safe 回落明暗态 token） |

## 二、T90-01B 关键决策（为什么不是 DWM acrylic）

- 实测矩阵：任务栏系统亚克力取色正常，但 **Electron 窗 backdrop 恒死灰** `#D3D3D3/#E1E1E1`
  （acrylic/mica × transparent 真假 × Electron 37/38 × 焦点/非焦点全验；
  `DwmGetUnmetMatchRequirements=0` 系统自评合格；disable-direct-composition 更糟=纯黑）。
  判定：企业版会话/Oray 虚拟显示驱动下 Chromium DirectComposition 拿不到壁纸共享，**不再赌 OS 层**。
- **壁纸衬底路线**：main 只读壁纸文件（注册表 WallpaperPath→data URL，≤8MB，只驻内存、
  不落日志不写盘）→ renderer 挂 `[data-wallpaper=1]` 铺壳层底 → 玻璃档各层撤实底色
  （`background-color`，绝不写 `background` 简写——简写会抹掉 T88 环境光光斑，t85 B1-g 实证）
  → 面板 backdrop-filter 磨的就是真壁纸像素 + 主题彩光斑。**全链路 Chromium 自合成 → 截图可客观验收**。
- 门控：glass 档 ∧ 壁纸读到才挂；pixel/linear/无壁纸 = 实心（绝不裸开透明，0.6.7 前行为零变化）。

### C 轮抓出的隐藏地雷（三轮 P1 红真因）
`'HKCU\Control Panel\Desktop'` 在前一轮接线时被写成**单反斜杠**（TS 里 `\C` 是非法转义被吞成 `C`）→ 键路径碎成 `HKCUControl PanelDesktop`；叠加 execFileSync 直调 reg.exe 被参数层二次吃斜杠、Get-ItemProperty 属性层大小写敏感漏掉本机真实值名 `WallPaper`（大写 P）。终修=PowerShell 注册表驱动 `Get-Item().GetValue()`（Win32 语义大小写不敏感 + drive 语法单引号无转义地狱）+ 双反斜杠字面量。**教训已固化**：Windows 注册表/路径进 TS 必须双反斜杠，且必须真机链路端到端探针验证——单测过≠包内对。

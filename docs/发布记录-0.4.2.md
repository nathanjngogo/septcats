## 流程偏差记录（vs publish.sh）

- publish.sh 的「先 sign 再改 latest.yml 路径」顺序会使 sig 与最终 yml 失配（0.3.0 时 yml 本已是点形式故未爆）。本轮改按 **归一化→sign→verify→上传** 正确顺序手动编排；publish.sh 待后续修正（挂账）。
- `gh api PATCH releases/latest -f name=…` 参数写法在本机 gh 版报 404/422，title 未改成（仍「Septcats latest (0.3.0)」）——不影响 feed 功能（updater 只读 yml/sig/包），挂账修脚本时用 `--latest -F name=...`。

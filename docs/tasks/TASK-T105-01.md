## 2. 清点方法与踩到的正则盲区（重要）
首轮用 `icon={X}` 精确正则清点 = 75 处 / 24 枚，**漏了四种真实形态**：
1. 三元表达式：`icon={item.done ? CheckCircle : Circle}`（`Circle` 被漏）；
2. 数据字段：`{ id: 'workbench', icon: Layout }`（`Layout` 被漏）；
3. 三元返回：`return command.id === 'page.new' ? Plus : GearSix`（`GearSix` 被漏）；
4. 变量透传：`icon={icon}`（2 处，来源需人工核）。
宽口径复扫（词边界 + 排除 import 行）才补齐 `Circle` / `Layout` / `GearSix` / `BookOpen` 四枚。
**教训**：审计正则只认 `icon={Ident}` 会让「换装完成」是假绿；t58 审计因此加了「应用面名字必须全部指向线族（displayName 前缀）+ 应用源码零像素族 import」两条反向护栏。

## 5. 视觉评审与回炉
- 评审指出的**真问题**（已修）：① `AiRobot` 16px 下天线+双眼+嘴糊成一团 → 撤嘴线、眼加长到 2.3；② `Trash` 桶内两条竖纹 16px 并成灰块 → 撤纹（轮廓自足）；③ `Shop` 与 `Home` 撞脸 → 加三枚雨棚条纹（平顶店面 vs 坡顶房子）。
- 评审的**误报**（核过后不改）：`Star` 24px「画歪」——逐点核算左右对称（外径 7.9/8.0、内径 3.9/4.05，镜像坐标完全对应）；`DotsThree`「实心圆」——实为三条 1.5 单位短划，零填充契约未破。
- 结论：24px（应用主档）全部达标；16px 下 31 枚中重细节枚（BookOpen/Calendar/FileText/Todo 等）仍有行业固有的细节损失，已在重细节枚上做减法。

## 6. 环境侧（写进 skill）
- Linux 主机跑本仓 jsdom 门禁：`NODE_OPTIONS=--no-experimental-webstorage`（或 `--localstorage-file=<path>`）——node 26 内建 `localStorage` 抢走 jsdom 的，否则 `localStorage.clear()` undefined → 上百用例假红。
- `perf.test.ts` 在本机（Linux）**干净 HEAD 亦红**：冷查 85.4ms（过）/ commitOps P95 64.8ms（预算 16ms，红）/ rebuild 3616ms（过）→ 环境敏感性观测，判红前先跑干净 HEAD 对照。

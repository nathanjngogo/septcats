## 目标（B1 = 纯后端，前端 UI 是 B2 另单）

给页面加「密码锁」：**正文块密文落库**，验证口令才解密；恢复码一次性；失败限速。
本单交付迁移+加密核心+主进程服务+IPC 通道+回归测试，做到 PM 能用单测/IPC 级探针验收全部安全语义。

## 范围（只增不改的「增」也列出落点）

1. **v10 迁移**（`apps/desktop/src/db/`，先读 `schema.v9.ts`+`migrations.ts` 照同款写法）：
   - 新表 `page_lock(page_id TEXT PRIMARY KEY, kdf_salt BLOB NOT NULL, verifier BLOB NOT NULL,
     recovery_verifier BLOB NOT NULL, wrapped_key BLOB NOT NULL, failures INTEGER NOT NULL DEFAULT 0,
     locked_until INTEGER NULL, updated_at INTEGER NOT NULL)`。
   - 新表 `block_cipher(page_id TEXT PRIMARY KEY, blob BLOB NOT NULL, format INTEGER NOT NULL DEFAULT 1,
     updated_at INTEGER NOT NULL)` —— 锁页的**正文块密文**（整页块 JSON 一份密文，粒度=页）。
   - 注册：`migrations.ts` 的 `MIGRATIONS` 数组**追加 `{ id: 10, name: 'v10-page-lock', up: applySchemaV10 }`**；
     `LATEST_SCHEMA_VERSION` 由数组自动导出（=10），**没有要手改的常量**。
   - ⚠ 版本双轴勿混（红线）：`packages/core/op.ts` 的 `SCHEMA_VERSION = 3` 是**对外 wire 格式**，
     **绝对不许动**（动了=老客户端段校验全炸）；本单只动 desktop 内部迁移轴。测试钉点已参数化
     （selftest/importer-exec 都引用 LATEST_SCHEMA_VERSION 常量，实测无写死 9 的钉——若发现写死项，
     随动并记 DEVIATION）。`MIN_SUPPORTED_SCHEMA_VERSION`（desktop 侧若有）不提高，core 零改动。
2. **加密核心**（新文件 `apps/desktop/src/main/lock.ts`，Node crypto 零新依赖）：
   - KDF：`scrypt(N=2^15, r=8, p=1, keylen=32)`（对齐仓内 `sync/crypto` 既有参数口径，先读它）。
   - 数据密钥 DK：随机 32B，主口令派生 MK 与恢复码派生 RK **各包一份**（AES-256-GCM
     envelope：`wrapped_key` 存 DK⓪MK；恢复码解出 DK 后可换口令重装）。参照/复用 `sync` 的信封写法但**不许改 sync 文件**。
   - verifier：对口令派生值加密一段固定明文探针（存 `verifier`），验证=解开比对，**绝不明文存口令**。
   - 恢复码：随机 20 字节 base32 分组（形如 XXXXX-XXXXX-…），RK 由**恢复码本身**派生；`recovery_verifier` 同理。恢复码**一次性**：使用成功后强制换口令（服务层置位+旧 wrapped 段作废重建）。
   - 限速：`page_lock.failures/locked_until`——错 5 次锁 60s（计数在表内持久，重启不重置）。
   - 正文：`setLock` 时把该页 blocks 明文读出 → DK 加密写 `block_cipher` → **删除明文块行**（FTS 随之消失）；
     `unlock` 校验通过后 DK 解密 → 写回块表（走既有 commit 通道使 op 账本合法）；锁页期间任何 `blocks.listByPage` 对**未验证会话**返回空且带 `locked:true` 标志（不报错、不泄露内容）。
   - 会话内解锁态：Map<pageId, DK>，仅存主进程内存；`lock:lock/lock:unlock/lock:disable` 后即时失效对应项；应用退出自然全灭。
3. **IPC**（preload+main 注册；通道名沿用总任务书 `lock:*`）：
   - `lock.getStatus {pageId}` → `{locked, failures, lockedUntil}`；`lock.setPass {pageId, pass, recoveryOut}`（生成并把恢复码经 out 参数回传一次，B2 弹展示）；`lock.verify {pageId, pass}`；`lock.recover {pageId, code, newPass}`（一次性）；`lock.changePass {pageId, oldPass, newPass}`；`lock.remove {pageId, pass}`（解密回明文+删锁）。
   - 全部错误走统一 error code（E_LOCK_NOT_SET/E_LOCK_BADPASS/E_LOCK_LOCKED/E_LOCK_RECOVERY_USED），**不把异常栈透给 renderer**。
4. **接线点**（最小改动，逐处记 DEVIATION）：
   - `pages.delete`（进回收站）遇锁页：连带删 `page_lock`+`block_cipher`（防孤儿密文）；
   - FTS/搜索：锁页明文块已删 → 自然不命中，补一枚「锁页不出现在搜索结果」回归测试；
   - 导出（exporter）遇锁页：输出 `{locked:true}` 占位，不带密文（读 export 链路的现状找最小挂点，找不到就记 DEVIATION 留给 B2 单）。
5. **测试**（新增 `apps/desktop/test/t67-lock.test.ts` 等，覆盖安全语义为主）：
   设锁→明文块消失/密文在表；错口令 5 次→lockedUntil 生效（时间注入测法）；正确口令→块还原逐字节相等且账本合法（对照既有 pages 回归）；恢复码用一次成功换口令、二次被拒；remove 后密文全灭明文回归；FTS 搜不到锁页内容；v10 迁移在 v9 夹具上升级成功；SCHEMA_VERSION 钉点回归。

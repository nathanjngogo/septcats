## T106-01 —— 箭头下拉菜单被裁（真缺陷，缺陷级最高）
**现象（像素级取证）**：菜单只剩左半截；切线是**一条笔直竖线且正好压在侧栏↔主区分界线上**；
切断处**没有菜单边框、圆角、阴影溢出** ⇒ **裁切**（clip）而非被遮挡（occlusion）；文字被从中间硬切。

**根因（找到了，不是猜）**：`packages/ui/src/looks.css` 的 **毛玻璃档**给
`.sc-shell__topbar` / `.sc-shell__sidebar` 加了 `backdrop-filter: blur(...)`。
按规范，`backdrop-filter` 会让元素成为 **fixed 后代的包含块** ⇒ 挂在侧栏里的
`position: fixed` 菜单改由**侧栏**定位并被侧栏边界裁剪。
极简 / 夜航仪表档没有这条材质 ⇒ 同一份代码只在毛玻璃档露馅（老板正好在用玻璃档）。

**修法（结构性，不是把 z-index 调大）**：新增 shell 级**浮层宿主**
（`renderer/layout/overlayHost.tsx` 的 `<FloatingLayer>` + `App.tsx` 里 `.app-overlay-host`，
位于侧栏祖先链之外）——侧栏三处浮层（工作区菜单 / 新建箭头菜单 / 页面行右键与 ⋯ 菜单）
全部门户化到宿主里；几何仍是 `position: fixed` + **视口坐标**（菜单 left/top 本来就取自
`getBoundingClientRect`），宿主零尺寸、不吃指针事件 ⇒ **几何与 z 轴语义零变化**，三档观感一致。
宿主缺失时回退就地渲染（裸组件单测如 `templates-ui` 仍绿）。

**实证**：`Septcats-Linux打包/T106-01-浮层裁剪复现.png` —— 同一份 DOM/CSS 并排对照
（浮层在侧栏内 = 被裁；挂宿主 = 完整）。渲染实测：侧栏内那枚 fixed 菜单的盒坐标被**改算成侧栏相对**
（x 从 212 → 239 = 侧栏左缘 + 212），正是"包含块被换掉"的机械证据。

**防复发**：① 结构契约测试 `nav-rail.test.tsx` 新增 —— 菜单的祖先链**不得穿过 `.sc-shell__sidebar`**，
且必须落在 `[data-testid="app-overlay-host"]` 内；② `looks.css` 那条材质规则旁写死结构约束注释
（侧栏/顶栏之内不得再挂 fixed 浮层）。

## T106-03 —— 「转为多维数据」后新建页面全是多维表格
**根因**：`PageView` 的 `dbPageId` 本地态**只设不清**（`convertToDatabase` 里 `setDbPageId(...)`
之后没有任何复位路径），而承载判定写的是 `if (dbPageId !== null) return <DbPage/>`。
转换过一次后，这个 `PageView` 实例（不随选中页重挂）对**任何**选中页都返回那一个 `DbPage`
⇒ 症状完全吻合：新建页面显示的还是多维表格；且 `rendersEditor` 同样含着 `dbPageId === null`，
编辑器也永不挂载（同一根因的第二症状）。

**修法**：把兜底判据从「本地态非空」改成「**当前选中页就是被转换的那一页**」：
```ts
const dbFallbackActive = dbPageId !== null && activePageId === dbPageId;
```
承载分支与 `rendersEditor` 同源消费该常量（单一出处，不留第二份规则）。
语义上"树注解优先、本地态只在转换瞬间兜底"的既有设计不变，只是**兜底不再粘滞**。

**契约测试**：`page-delete-ui.test.tsx` 新增 —— 转换后把选中切到另一页，`新建记录`（库 UI）必须消失。

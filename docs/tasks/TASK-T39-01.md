# TASK-T39-01 · R3：布局设计器（预设 + 参数 + 导入导出）

> PM：Hermes ｜ P1（老板新需求 R3）｜ 前置：T38-01 收口（AI 面板落地后再做——设计器要能配置它）
> 老板口径：「希望学习 Hermes 的设计，有个布局设计器」+ 已确认「**预设**（不做任意拖拽面板）」

## 0. 目标与范围

给用户一个**布局设计器**：先给**预设**，再允许**参数微调**，并能**导出/导入**布局 JSON。

**必须做到**：
1. **预设（三选）**：
   - `notion`（默认）：侧栏左 + 内容居中（measure 650）+ 标签条显 + AI 面板右侧收起 + 密度舒适
   - `focus`（宽屏专注）：侧栏收起 + 大 measure（~900）+ 标签条显 + AI 面板收起
   - `workbench`（工作台）：侧栏左（240）+ measure 650 + 标签条显 + **AI 面板右侧展开**
   切换预设**即时生效**且**持久化**。
2. **参数微调**（全部持久化）：
   - 侧栏：位置（左 / 收起）· 宽度（200–320，夹紧）
   - 内容：最大宽度 measure（560–1000，夹紧）
   - AI 面板：位置（右 / 底 / 隐藏）· 默认展开与否
   - 标签条：显 / 隐
   - 主题：浅 / 深 / 跟随系统（复用既有主题机制，不新造）
   - 密度：紧凑 / 舒适（影响行高与间距档位，走 token 档位，不许写死值）
3. **实现口径**：所有参数以 **CSS 变量**注入根节点（如 `--sc-layout-measure`、`--sc-layout-sidebar`），既有布局消费这些变量；**不得**用 JS 直接量测/内联改宽高的方式（可维护、可测试）。
4. **存储**：一份布局 JSON（`septcats.layout`，全局即可，不必按 workspace），损坏时回退默认；**导出/导入**：MVP = **导出到剪贴板 + 从剪贴板文本导入**（避免新增文件对话框 IPC）；导入非法 JSON 要给出可读错误且不改动当前布局。
5. **入口**：设置页新增「**布局**」区块（预设卡片 + 参数控件 + 导出/导入按钮）；命令面板加「切换布局预设」命令（循环或选择）。
6. **不做**：任意拖拽/浮动面板、多窗口、每页独立布局。

## 1. 验收（数值化/真机）

1. **预设切换即时生效**：切 `notion→focus→workbench`，断言侧栏宽/measure/AI 面板可见性随之变化（贴实测数值）；重开应用保持在最后选的预设。
2. **参数夹紧**：宽度输入 100 / 999 时被夹到 200 / 320（断言实际值）。
3. **导入导出往返**：导出 → 修改 → 导入原 JSON → 布局**逐字段等价**（断言 JSON 深比较）。
4. **非法导入**：贴入 `{bad json` → 显示可读错误、布局不变（断言）。
5. **四条红线全部保持**（回归断言/真机）：① 窗口零滚动；② 侧栏可**完全收起**（width=0，不是窄轨）；③ 块手柄装订线 `gutter ≥ 8`；④ 对比度门禁（`packages/ui/test/contrast.test.ts`）绿；另加 ⑤ 多页签（T37）与 AI 面板（T38）行为不变。
6. 双主题 × 四态截图；`no-magic`、`build-tokens --check` 通过。
